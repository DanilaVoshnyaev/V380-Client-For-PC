# Как добавить свою камеру в базу

База отвечает на один вопрос: **можно ли вытащить видео из этой камеры мимо
облака вендора, и если да — как именно.** Каждая новая запись экономит кому-то
несколько часов поисков по форумам.

## Быстрый путь

```
python probe.py <IP-вашей-камеры> --user admin --password ВАШ_ПАРОЛЬ --report
```

Инструмент опросит камеру и положит заготовку в `reports/<id>.json`.
**В заготовку не попадают ни ваш IP, ни пароли, ни серийный номер камеры** —
только признаки модели, общие для всех таких устройств. Проверьте файл глазами
перед отправкой, это никогда не лишнее.

Дальше:

1. Заполните поля, помеченные `ЗАПОЛНИТЕ`.
2. Перенесите файл в `db/devices/`. Имя файла должно совпадать с полем `id`.
3. Проверьте: `python tools/validate_db.py`
4. Отправьте pull request, добавив в описание строку о согласии с
   [CLA.md](CLA.md) — см. раздел «Лицензия и согласие участника» ниже.

## Что обязательно заполнить руками

Инструмент видит камеру по сети, но не знает главного — **как вы её разлочили**.
Именно это и есть ценность записи.

| Поле | Что писать |
|---|---|
| `aliases` | Под каким брендом камера продаётся. Одно железо часто идёт под пятью именами |
| `cloud_app` | Родное приложение: V380 Pro, iCSee, YCC365, Tuya Smart… |
| `unlock.app_path` | Где именно в приложении лежит настройка |
| `unlock.steps` | Пошагово, по шагу на строку. Пишите так, как объясняли бы соседу |
| `unlock.requires_reboot` | Нужна ли перезагрузка камеры. Очень частая причина «не заработало» |

## Статусы доступа

| Статус | Когда ставить |
|---|---|
| `open` | ONVIF и RTSP работают из коробки |
| `hidden-onvif` | ONVIF есть, но выключен с завода; включается в приложении |
| `closed` | Штатных способов нет: камера только слушает своё облако |
| `firmware-mod` | Поток доступен только после смены прошивки |

Запись со статусом `closed` — тоже полезный вклад. Она экономит людям вечер
бесплодных попыток.

## Требования к качеству

- **Проверьте на своей камере.** Записи «по слухам с форума» не принимаются.
- **Нужен хотя бы один сильный признак** для опознавания: `onvif_manufacturer`,
  `rtsp_banner` или `http_server`. По одним портам и MAC камеру не отличить.
- **Укажите версию прошивки.** Поведение между версиями заметно различается.
- **Заполните `security.rtsp_without_auth`.** Если поток отдаётся без пароля,
  владелец камеры обязан об этом знать.

## Чего в базе быть не должно

Это справочник по **вашему собственному оборудованию**, а не инструмент для
чужого. В pull request не принимаются:

- пароли по умолчанию, списки учётных данных, подбор паролей;
- эксплойты, обход авторизации, уязвимости прошивок;
- чужие IP-адреса, ссылки на публично доступные камеры, результаты сканирования
  интернета;
- любые серийные номера, облачные ID и MAC целиком — только префикс OUI
  из трёх байт.

Pull request с таким содержимым будет закрыт.

## Проверка перед отправкой

```
python tools/validate_db.py
```

Она же запускается автоматически на каждый pull request. Валидатор ловит
битый JSON, неизвестные поля, несовпадение имени файла с `id`, дубликаты,
неверный формат MAC и даты, а также забытые пометки `ЗАПОЛНИТЕ`.

## Правки в существующих записях

Приветствуются: добавить версию прошивки в `match.firmware`, уточнить шаги,
дописать алиас бренда, отметить неработающую функцию. Если поведение вашей
прошивки отличается принципиально — заведите отдельную запись, а не ломайте
существующую.

## Лицензия и согласие участника

В проекте две лицензии, и это сделано намеренно:

| Что | Лицензия | Почему так |
|---|---|---|
| Код (`*.py`, `tools/`, сборка) | MIT — [LICENSE](LICENSE) | Кода немного, он легко повторяется. Берите и делайте что хотите. |
| База устройств (`db/`) | CC BY-SA 4.0 — [db/LICENSE](db/LICENSE) | Каждая запись — чей-то потраченный вечер. Производная база обязана остаться открытой, чтобы собранное сообществом нельзя было приватизировать. |

Копилефт базы касается только данных. Подключить её к своему закрытому
приложению можно.

Отправляя первый pull request, добавьте в его описание строку:

```
Я прочитал(а) CLA.md и согласен(на) с его условиями.
```

[CLA.md](CLA.md) оставляет авторские права на вклад за вами, но позволяет
автору проекта выпускать проект и на других условиях, включая платные.
Без такого разрешения открытая часть застывает навсегда, а это плохо и для
проекта, и для тех, кто в него вкладывается. Документ короткий, прочитайте
его целиком — там же объяснено, чего он **не** делает.

Не готовы соглашаться? Заведите issue с описанием своей камеры и данными от
`--report`. Автор оформит запись сам — это тоже полноценный вклад.
