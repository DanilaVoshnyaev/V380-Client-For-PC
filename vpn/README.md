# Доступ к камерам с телефона через WireGuard

Телефон из любой сети попадает в домашнюю сеть и видит камеры так, будто
стоит рядом с ними. Наружу торчит только один UDP-порт WireGuard, который
на неавторизованные пакеты не отвечает вообще.

**Порты камеры (554, 8899) наружу не пробрасываются никогда.** У этой прошивки
RTSP отдаётся без пароля — камеру найдут сканерами за сутки.

Дома, в той же сети Wi-Fi, VPN не нужен: в клиенте есть кнопка
**Смотреть на телефоне…** с QR-кодом потока.

## Схема

    Телефон (любая сеть)
        │  UDP 51820
        ▼
    Роутер ──проброс──> ПК с WireGuard (10.8.0.1)
                              │ NAT
                              ▼
                        Камера 192.168.1.100

## Настройка: четыре шага

### 1. Установить WireGuard на ПК

    winget install --id WireGuard.WireGuard -e

### 2. Настроить ПК одной командой

    python vpn/wg_setup.py --install

Windows спросит права администратора — согласитесь. Скрипт сам:

- узнаёт внешний адрес роутера и домашнюю подсеть;
- создаёт ключи и конфиги: `server-wg0.conf` для ПК, `phone.conf` и
  `phone-qr.png` для телефона;
- ставит туннель службой — он поднимается сам после перезагрузки;
- включает маршрутизацию и NAT между туннелем и домашней сетью;
- открывает UDP 51820 в брандмауэре.

В конце он напечатает адрес ПК, который нужен для роутера.

Повторный запуск берёт уже созданные ключи, так что настроенный телефон не
отвалится. Посмотреть команды, ничего не меняя: `--install --dry-run`.
Убрать всё: `--uninstall`.

Внешний адрес скрипт узнаёт у сервиса api.ipify.org — изнутри сети его
больше никак не определить. Если не хотите этого запроса или у вас DDNS-имя,
задайте адрес сами: `--endpoint ИМЯ_ИЛИ_АДРЕС`.

### 3. Настроить роутер

В веб-интерфейсе роутера (обычно `192.168.1.1`):

1. **Закрепить адрес за ПК.** ПК получает IP по DHCP и после перезагрузки
   может стать другим — проброс тогда перестанет работать. Найдите ПК в списке
   клиентов и включите привязку к MAC (DHCP reservation) на адрес, который
   напечатал скрипт.
2. **Проброс порта.** Раздел переадресации портов:
   протокол **UDP**, внешний порт `51820`, внутренний адрес — адрес ПК,
   внутренний порт `51820`.

### 4. Настроить телефон

1. Установить WireGuard из Google Play или App Store.
2. Добавить туннель → **Сканировать QR-код** → навести на `vpn/phone-qr.png`.
3. Включить туннель.

Конфиг телефона намеренно пропускает через туннель **только домашнюю сеть**
(`AllowedIPs = 192.168.1.0/24, 10.8.0.0/24`). Обычный трафик телефона идёт
напрямую и не замедляется.

## Проверить

Телефон перевести на мобильный интернет, Wi-Fi выключить. Включить туннель
и открыть в VLC или tinyCam:

    rtsp://192.168.1.100:554/live/ch00_0

Проще всего взять ссылку из QR-кода в клиенте: через туннель она работает
так же, как дома.

В tinyCam Pro можно добавить камеру по ONVIF (`192.168.1.100:8899`) и получить
поворот, зум и пресеты.

## Важные оговорки

**Провайдерский NAT.** Если WAN-адрес в настройках роутера не совпадает с вашим
публичным IP — вы за NAT провайдера, и проброс порта работать не будет.
Скрипт ловит очевидный случай (адрес вида 100.64.x.x–100.127.x.x), но не все. В этом
случае нужен либо публичный IP от провайдера за доплату, либо Tailscale,
которому проброс не требуется.

**Публичный IP может смениться.** Если провайдер выдаёт динамический адрес,
`Endpoint` в конфиге телефона однажды перестанет отвечать. Решение — DDNS
(бесплатный DuckDNS или сервис самого роутера): сгенерируйте конфиги заново
с `--endpoint ваше-имя.duckdns.org` и отсканируйте новый QR-код.

**NAT в Windows может быть только один.** Если его уже создали Docker или WSL,
шаг NAT не пройдёт. Проверить: `Get-NetNat`.

**Прокси-клиент на ПК.** Если на машине работает VPN- или прокси-клиент,
забирающий маршрут по умолчанию, он перехватывает исходящий трафик и может
помешать WireGuard. Признак: туннель поднимается, но камера недоступна —
выключите такой клиент и проверьте снова.
Входящие пакеты на UDP 51820 приходят по локальной сети и перехвату не подлежат,
проблема возможна только с ответным трафиком.

**ПК должен быть включён.** WireGuard работает, пока работает машина. Если нужен
круглосуточный доступ — переносите сервер на Raspberry Pi или роутер с OpenWrt.

## Добавить ещё устройство

    python vpn/wg_setup.py --peers phone laptop planshet
    python vpn/wg_setup.py --install

Каждому устройству выдаётся свой ключ и свой адрес в туннеле. Первая команда
перевыпускает все ключи, поэтому QR-коды нужно отсканировать заново на всех
устройствах. Вторая переустанавливает туннель на ПК с новым конфигом.

## Что делает --install, если хотите вручную

PowerShell **от имени администратора**:

    # туннель службой
    & 'C:\Program Files\WireGuard\wireguard.exe' /installtunnelservice "$PWD\vpn\server-wg0.conf"

    # маршрутизация: туннель и сетевой адаптер домашней сети
    Set-NetIPInterface -InterfaceAlias 'server-wg0' -Forwarding Enabled
    Set-NetIPInterface -InterfaceAlias 'Беспроводная сеть' -Forwarding Enabled

    # NAT: без него камера получит пакет от 10.8.0.2, не будет знать
    # обратного маршрута и ответит в никуда
    New-NetNat -Name WGCameras -InternalIPInterfaceAddressPrefix 10.8.0.0/24

    # брандмауэр
    New-NetFirewallRule -DisplayName 'WireGuard cameras' -Direction Inbound -Protocol UDP -LocalPort 51820 -Action Allow -Profile Any

Конфиги без установки: `python vpn/wg_setup.py` (или с `--endpoint` и `--lan`,
чтобы задать адреса самому).
